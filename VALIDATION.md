# Проверка версии 7

В текущей Linux-среде отсутствуют .NET SDK и Windows Desktop workload, а загрузка SDK заблокирована политикой сети, поэтому реальный `dotnet build` WPF-проекта здесь выполнить невозможно. Выполнены доступные статические проверки.

## Пройдено

- XML-проверка всех XAML, `.csproj` и `app.manifest` — успешно (7 XAML-файлов, включая новое окно статистики).
- JSON-проверка `planner.settings.json` — успешно.
- Проверка парных скобок/кавычек C# с учётом обычных, дословных (`@"`) и «сырых» (`"""`) строк, а также комментариев — успешно для всех 44 файлов.
- Проверка обработчиков событий XAML против code-behind: все `Click`, `MouseDoubleClick`, `ContextMenuOpening`, `SelectedItemChanged`, `Drop`, `DragOver` и `DragLeave` имеют методы с совпадающими именами.
- Проверка путей привязок `{Binding …}` против объявленных свойств моделей и view-моделей — неизвестных свойств не найдено.
- Проверка `x:Name`, используемых из code-behind (`SearchBox`, `TimeScroll`, `TaskCanvas`, `DateOnlyCanvas`, `TimeLabels`).

## Что проверялось вручную по коду

- Двойной щелчок обрабатывается в `PreviewMouseLeftButtonDown` по `ClickCount >= 2`: перетаскивание в этот момент не стартует (`_dragTask = null`), событие помечается обработанным, поэтому обработчик пустой сетки не создаёт лишнюю задачу. Окно открывается через `Dispatcher.InvokeAsync(..., DispatcherPriority.Input)` — уже после того, как WPF завершит обработку щелчка и отпустит захват мыши.
- В режиме «Месяц» одиночный щелчок только выделяет задачу (`SelectTask`), открытие перенесено на `MouseDoubleClick`.
- Статистика считает просрочку тем же свойством `TaskItem.IsOverdue`, что и календарь, поэтому отчёт не может разойтись с цветами карточек.
- Запрос статистики использует параметры `$u0…$uN` для списка пользователей — конкатенации значений в SQL нет.
- Список шаблонов повторения привязан к отдельному свойству `SelectedTemplate`, поэтому обновление данных больше не сбрасывает задачу, выбранную в календаре.

## Финальная проверка на Windows

После распаковки выполнить:

```powershell
.\build.ps1
```

Затем:

```powershell
.\publish.ps1 -Runtime win-x64
```

Ручной сценарий приёмки:

1. Двойной щелчок по задаче в режимах «День», «Рабочая неделя», «Месяц» и в списке шаблонов — открывается окно задачи.
2. Двойной щелчок по свободному месту сетки — создаётся задача на выбранное время.
3. Перетаскивание и изменение длительности карточки продолжают работать (двойной щелчок их не ломает).
4. Кнопка «📊 Статистика»: строки по подчинённым, итоговая строка, смена периода, экспорт в CSV и открытие файла в Excel.
5. Поиск и флажок «Скрыть выполненные» фильтруют календарь без задержек и без обращения к сетевой базе.

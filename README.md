# SP Team Sync

Многопользовательский форк [Super Productivity](https://github.com/johannesjo/super-productivity): планировщик задач с современным UI, регулярными задачами, напоминаниями (включая при закрытой вкладке) — плюс **синхронизация между несколькими пользователями через общие рабочие пространства**, авторизация и админка.

Развёртывается в локальной сети организации без домена. Одна SQLite-база, ничего внешнего.

## Что внутри

- **Клиент** — оригинальный собранный веб-билд Super Productivity (лежит в `sp-dist/`, доступен по `/app/`).
  - Задачи, проекты, теги, таймеры, регулярные задачи, напоминания (в т.ч. когда вкладка закрыта — стандартный сервис-воркер SP), заметки, доски, планировщик недели.
- **Backend (Python, FastAPI)** — авторизация + WebDAV-сервер, к которому SP синкается.
  - JWT для админки и WebDAV Basic Auth для клиента.
  - «Рабочее пространство» = один WebDAV-каталог с списком участников. Все члены синкаются в одну и ту же папку — задачи, проекты, таймеры становятся общими.
  - Один пользователь может состоять в нескольких пространствах и переключаться между ними в SP.
- **Админка** (`/admin`) — создание/редактирование пользователей и пространств, инструкция подключения SP.

## Развёртывание на Windows (одним кликом)

1. Копируем папку на сервер (любая машина в LAN).
2. Дважды кликаем `install.bat` — создаст venv, поставит зависимости, сгенерирует HTTPS-сертификат.
3. Дважды кликаем `run.bat` — сервер поднимается на `https://<IP-этой-машины>:8443`.
4. (Опционально) `install_service.bat` — автозапуск при входе в Windows.
5. В firewall разрешаем входящие подключения на TCP 8443.

Python 3.11+ должен быть установлен. Node.js **не нужен** — SP уже собран и лежит в репозитории.

## Первый вход

1. Откройте `https://<IP>:8443/admin`, зарегистрируйте первого пользователя — он станет администратором.
2. В админке создайте пользователей (кнопка «+ Создать» в разделе «Пользователи»).
3. Создайте рабочее пространство и добавьте туда участников.
4. Каждому участнику покажите инструкцию «Как подключить» (кнопка на карточке пространства).

## Как подключить Super Productivity

Пользователь открывает `https://<IP>:8443/app`, дальше в самом SP:

- `Settings → Sync & Export/Import → Sync provider: WebDAV`
- **Base URL:** `https://<IP>:8443/webdav/<slug-пространства>/`
- **Sync folder path:** `sp`
- **Username / Password:** его логин/пароль на этом сервере

Нажимает `Save & sync now` — и клиент начинает жить в общей папке пространства.

## HTTPS-сертификат

Web Push, сервис-воркер SP и WebDAV — всё это требует HTTPS. Скрипт `scripts/make_cert.py` генерирует self-signed сертификат для `localhost`, IP этой машины и любых имён из аргументов:

```
python scripts/make_cert.py 192.168.1.10 planner.local
```

Чтобы браузеры не ругались, установите `data/cert.pem` в «Доверенные корневые центры сертификации» на каждом клиентском ПК (или разложите через GPO).

## Обновление Super Productivity

В репозитории лежит уже собранный `sp-dist/`. Если хотите пересобрать из свежих исходников:

- Linux/macOS: `./scripts/build_sp.sh` (нужен Node.js 20+)
- Windows: `bash scripts/build_sp.sh` из Git Bash, либо повторите его команды вручную

## Про многопользовательский режим

Super Productivity изначально — приложение локальное на одного пользователя. Мы используем его встроенный WebDAV-провайдер и общий каталог, чтобы дать нескольким пользователям общий набор данных. Конфликты одновременных правок разрешает сама SP (op-log модель): последний писатель побеждает по каждой сущности, но не по всему файлу целиком.

Практика:
- Отлично работает для 2–10 человек команды, если правки распределены по времени.
- При одновременной правке одной и той же задачи может выскочить диалог разрешения конфликта в SP — это её штатный механизм.

## Данные

- `data/app.db` — SQLite (пользователи, пространства, членства).
- `data/webdav/<slug>/` — файлы синхронизации SP по каждому пространству.
- `data/cert.pem`, `data/key.pem` — TLS.

Бэкап: скопировать папку `data/`.

## Настройка

`.env` в корне:

```
SECRET_KEY=<длинная случайная строка>       # обязательно смените в проде
ACCESS_TOKEN_TTL_MINUTES=10080
```

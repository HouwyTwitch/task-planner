# Общие задачи

Планировщик задач на основе [Super Productivity](https://github.com/johannesjo/super-productivity), доработанный для совместной работы:

- **статический сайт** — никакого сервера, только файлы;
- **синхронизация через общий файл** в сетевой папке — все участники работают с одним каталогом;
- **передача задач между людьми** — отправил, коллега принял или отклонил, вам пришло уведомление;
- всё на русском.

## Что доработано в Super Productivity

Super Productivity — приложение для одного человека, поэтому добавлены две вещи. Обе снаружи ядра, поэтому обновлять апстрим несложно.

**1. Провайдер синхронизации через папку в браузере** (`patch/local-file-web/`)

В апстриме синхронизация с локальным файлом собирается только для Electron и Android. Для веба её нет. Добавлен провайдер на File System Access API: браузер даёт постоянный доступ к выбранной папке, включая сетевой каталог, подключённый как диск. Реализован по штатному контракту `FileAdapter` и регистрируется в родной фабрике провайдеров.

**2. Плагин «Передача задач»** (`plugin/`)

Написан на публичном API плагинов Super Productivity — ядро не трогает. Хранит свои данные через `persistDataSynced`, поэтому они едут через **тот же общий файл**, что и задачи.

Ответственный за задачу обозначается тегом участника (`Иван Петров`). При принятии передачи плагин снимает тег отправителя и ставит тег получателя. Благодаря этому «чьи задачи» видно и без плагина — штатной фильтрацией по тегу.

### Как устроена одновременная работа с файлом

Несколько человек пишут в один файл, поэтому данные плагина хранятся не как готовое состояние, а как **журнал операций**: «предложил задачу», «принял», «отклонил». Операции неизменяемы и имеют уникальные идентификаторы, поэтому слияние двух версий файла — это объединение множеств, без потерь. Текущее состояние получается свёрткой журнала.

Сами задачи синхронизирует Super Productivity своим механизмом op-log — он тоже рассчитан на слияние, а не на перезапись.

## Сборка не требуется

Готовая сборка лежит в репозитории — папка `site/`. Ни Node.js, ни Git на рабочих местах не нужны: скопировали папку проекта и запустили.

Пересобирать нужно, только если вы правите плагин или провайдер, либо хотите подтянуть свежую версию Super Productivity — см. «Пересборка» ниже.

## Запуск

```
start.bat        (Windows)
./start.sh       (Linux, macOS)
```

Откроется `http://localhost:4321`.

**Почему нужен локальный сервер, а не двойной клик по `index.html`.** Доступ к папке (File System Access API) браузер даёт только в защищённом контексте — это HTTPS либо `localhost`. Файл, открытый через `file://`, такого доступа не получает. Локальный сервер — самый простой способ получить `localhost`, и он не требует ни сертификата, ни настройки сети.

Папку `site/` вместе с `start.bat` можно положить прямо в сетевую папку — каждый запускает её со своего места.

## Настройка синхронизации (один раз на каждом рабочем месте)

1. Положите в общую сетевую папку каталог для синхронизации, например `\\сервер\Общие\Задачи`. Подключите его как сетевой диск, чтобы он был виден в проводнике.
2. Запустите `start.bat`.
3. При первом запуске плагин спросит ваше имя — под ним вас увидят коллеги.
4. `Настройки → Синхронизация` → провайдер **Локальная папка** → **Выбрать папку** → укажите общий каталог и разрешите доступ.
5. Нажмите синхронизацию.

После перезапуска браузера доступ к папке нужно подтвердить одним кликом — это требование браузера, папку заново искать не придётся.

**Браузер:** Chrome или Edge. В Firefox и Safari нет File System Access API, поэтому синхронизации через папку там не будет.

## Как передать задачу

1. Откройте панель **Передача задач** (кнопка в шапке или в боковой панели).
2. Вкладка **Мои задачи** → у нужной задачи нажмите **Передать**.
3. Выберите коллегу, при желании добавьте сообщение, отправьте.
4. После синхронизации коллега увидит предложение во **Входящих** и нажмёт **Принять** или **Отклонить** (с причиной).
5. Вам придёт уведомление о его решении. При принятии задача переходит на него, при отклонении остаётся за вами.

Пока коллега не ответил, задача помечена как ожидающая, и её можно **Отозвать**.

## Важные особенности

**Синхронизация не мгновенная.** Обмен идёт через файл, поэтому события доходят при очередной синхронизации, а не в ту же секунду. Настроить периодичность можно в настройках синхронизации Super Productivity.

**Уведомления привязаны к рабочему месту.** Файл не хранит, кто что прочитал, поэтому отметки о показанных уведомлениях лежат локально. На другом компьютере того же человека уведомление покажется заново.

**Проверка личности не предусмотрена.** Участник — это имя, введённое при первом запуске. Модель рассчитана на доверенную сеть организации, где доступ ограничен правами на сетевую папку. Пароли и разграничение доступа внутри файла не поддерживаются.

**Резервная копия — это копия папки синхронизации.** Больше нигде данные не хранятся.

## Структура репозитория

```
plugin/                 плагин «Передача задач»
  core.js               журнал операций: участники, передачи, слияние
  plugin.js             фон: профиль, уведомления, кнопки
  index.html            панель: мои задачи / входящие / отправленные / участники
patch/
  local-file-web/       веб-провайдер синхронизации через папку
  apply.mjs             вживляет доработки в клон Super Productivity
scripts/
  build.sh / build.bat  сборка статического сайта
  serve.mjs             локальный сервер для site/
site/                   результат сборки (появляется после build)
```

`sp-src/` (клон Super Productivity) в репозиторий не входит — его создаёт скрипт сборки.

## Пересборка

Нужна, только если вы меняли плагин или провайдер, либо хотите свежую версию Super Productivity. Требуются **Node.js 20+** и **Git**.

```
scripts\build.bat        (Windows)
./scripts/build.sh       (Linux, macOS)
```

Скрипт клонирует Super Productivity, вживляет доработки и пересобирает `site/`. Чтобы подтянуть свежий апстрим, сначала удалите `sp-src/`. Вживление идемпотентно и внятно сообщит, если точка вставки в апстриме сдвинулась и патч пора поправить.

Из собранного `site/` вырезается плагин Google Calendar: он несёт OAuth client id разработчиков Super Productivity, из-за чего защита от секретов в GitHub блокирует коммит сборки. В локальной сети без интернета плагин всё равно бесполезен. Если календарь нужен, уберите соответствующую строку в скрипте сборки.
